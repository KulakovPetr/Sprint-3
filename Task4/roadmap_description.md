# Описание RoadMap реализации MVP

## Общая структура RoadMap

RoadMap разделён на два основных периода:
- **MVP (6 месяцев)** — промежуточное состояние, где клиент может открыть депозит онлайн, но заявки обрабатываются бэк-офисом вручную
- **Целевое решение (12 месяцев)** — полная автоматизация, бэк-офис не участвует в процессе открытия депозитов

## Детализация по этапам

### Месяц 1-2: Фундамент инфраструктуры и АБС

**Инфраструктура:**
- Развёртывание кластера Apache Kafka (2 недели)
- Настройка SFTP-сервера в DMZ для партнёрского кол-центра (1 неделя)
- Настройка балансировщика нагрузки (1 неделя)

**АБС:**
- Начало разработки REST API поверх PL-SQL процедур (4 недели, продолжается до месяца 3)
- Начало разработки модуля управления ставками в АБС (замена Excel-процесса) (3 недели, продолжается до месяца 2)

**Сервис депозитов:**
- Проектирование архитектуры микросервиса (1 неделя)
- Разработка REST API для управления ставками (2 недели)

### Месяц 2-3: Разработка сервиса депозитов и интеграция

**Сервис депозитов:**
- Завершение API для ставок
- Разработка REST API для подачи и обработки заявок на депозит (3 недели)
- Интеграция с Kafka (публикация событий) (2 недели)
- Создание БД PostgreSQL (1 неделя)

**АБС:**
- Завершение REST API
- Завершение модуля ставок
- Интеграция с Kafka (подписка на заявки) (2 недели)

**Интернет-банк:**
- Разработка .NET Core адаптера для Kafka (3 недели, начинается в месяце 2)
- Развёртывание API Gateway (2 недели)

### Месяц 3-4: UI и интеграции

**Интернет-банк:**
- Разработка UI для просмотра депозитов и подачи заявки (3 недели)
- Реализация подтверждения через СМС-код (2 недели)
- Оптимизация загрузки справочных данных (кэширование) (1 неделя)

**Сайт:**
- Разработка страницы депозитов с актуальными ставками (2 недели)
- Разработка формы подачи заявки (1 неделя)
- Интеграция с API сервиса депозитов (1 неделя)
- Интеграция с системой кол-центра (1 неделя)
- Настройка TLS/HTTPS (1 неделя)

**Система кол-центра:**
- Разработка микросервиса rates-consumer (2 недели)
- Разработка UI-раздела «Ставки по депозитам» (2 недели)
- Обработка заявок с сайта (2 недели)

**Сервис депозитов:**
- Реализация SFTP-экспорта для партнёрского кол-центра (2 недели)
- Реализация механизма персонализированных ставок (2 недели)

### Месяц 4-5: Доработки и оптимизация

**Интернет-банк:**
- Настройка горизонтального масштабирования (2 недели)
- Настройка отказоустойчивости (резервный ЦОД) (2 недели)

**АБС:**
- Оптимизация производительности БД Oracle (2 недели)

**Сервис уведомлений:**
- Разработка микросервиса уведомлений (2 недели)
- Интеграция с СМС-шлюзом (1 неделя)

**Инфраструктура:**
- Настройка мониторинга и алертинга (2 недели)
- Настройка резервного ЦОД для новых сервисов (2 недели)

### Месяц 5-6: Тестирование и запуск MVP

**Все системы:**
- Интеграционное тестирование (2 недели)
- Тестирование API и модулей (2 недели)
- Документирование API (2 недели)

**Запуск MVP:**
- Поэтапный запуск в production
- Мониторинг и устранение проблем
- Обучение сотрудников новым процессам

## Целевое решение (Месяц 7-12)

### Месяц 7-9: Автоматизация обработки заявок

**АБС:**
- Разработка модуля автоматической обработки заявок на депозит (3 недели)
- Интеграция с бизнес-правилами для автоматического согласования ставок
- Устранение необходимости ручной обработки заявок бэк-офисом

**Интернет-банк:**
- Начало полной миграции на микросервисную архитектуру
- Постепенный отказ от монолита

### Месяц 10-12: Полная автоматизация и расширение

**Интернет-банк:**
- Завершение миграции на микросервисы
- Полная автоматизация процесса открытия депозитов

**Сайт:**
- Добавление функционала подачи заявок на кредиты (следующий этап развития)

**Финальное состояние:**
- Клиент открывает депозит полностью автоматически в интернет-банке
- Бэк-офис не участвует в процессе открытия депозитов
- При обращении в отделение задействованы только сотрудники фронт-офиса
- Сокращение операционных издержек на открытие новых депозитов

## Критические зависимости

1. **Kafka должна быть развёрнута до начала разработки интеграций** (месяц 1)
2. **REST API АБС должен быть готов до интеграции сервиса депозитов** (месяц 2-3)
3. **Сервис депозитов должен быть готов до разработки UI в интернет-банке** (месяц 3)
4. **Все компоненты должны пройти интеграционное тестирование перед запуском** (месяц 5-6)

## Риски и митигация

- **Риск задержки разработки АБС API:** Митигация — параллельная разработка mock-сервисов для тестирования
- **Риск проблем с интеграцией Kafka:** Митигация — ранний POC в месяце 1
- **Риск перегрузки при запуске:** Митигация — постепенный rollout, мониторинг нагрузки
