# Проект: Цифровая трансформация банка «Стандарт»

## Описание проекта

Проект представляет собой архитектурное решение для цифровой трансформации банка «Стандарт» в рамках развития онлайн-каналов обслуживания клиентов. Основная цель — реализация MVP для открытия депозитов и накопительных счетов онлайн через интернет-банк и сайт банка.

## Структура проекта

Проект состоит из 4 заданий, каждое из которых находится в отдельной директории:

### Task1 — Карта IT-ландшафта и схема интеграции приложений

**Файлы:**
- `IT_landscape_map.drawio` — карта IT-ландшафта в формате draw.io (XML)
- `IT_landscape_map.png` — PNG-версия карты IT-ландшафта
- `integration_schema.drawio` — схема интеграции приложений в формате draw.io
- `integration_schema.png` — PNG-версия схемы интеграции

**Описание:**
- Карта IT-ландшафта показывает соответствие между организационной структурой банка (строки) и бизнес-возможностями второго уровня (столбцы)
- Схема интеграции отображает текущее состояние (AS-IS) интеграций между системами банка с указанием участников процессов

### Task2 — FURPS+ таблица требований

**Файлы:**
- `FURPS+.md` — таблица требований в формате Markdown

**Описание:**
Таблица содержит архитектурно-значимые требования, сгруппированные по категориям:
- **F** — Функциональные требования (12 требований)
- **U** — Удобство использования (4 требования)
- **R** — Надёжность (5 требований)
- **P** — Производительность (5 требований)
- **S** — Поддерживаемость (4 требования)
- **+R** — Ограничения (9 требований)

Каждое требование содержит комментарий с обоснованием.

### Task3 — ADR: Открытие депозитов онлайн (MVP)

**Файлы:**
- `ADR.md` — архитектурное решение в формате ADR (Architecture Decision Record)
- `C4_context.drawio` — диаграмма контекста C4 (draw.io) — **основной формат для редактирования**
- `C4_context.puml` — диаграмма контекста C4 (PlantUML)
- `C4_context.png` — PNG-версия диаграммы контекста (для быстрого просмотра)
- `C4_containers.drawio` — диаграмма контейнеров C4 с детализацией интернет-банка и АБС (draw.io) — **основной формат для редактирования**
- `C4_containers.puml` — диаграмма контейнеров C4 (PlantUML)
- `C4_containers.png` — PNG-версия диаграммы контейнеров (для быстрого просмотра)

**Описание:**
ADR содержит:
- 6 Use Cases с пошаговым описанием
- 14 нефункциональных требований
- Детальное описание архитектурного решения (микросервисная архитектура, Kafka, API Gateway)
- Альтернативные решения и их анализ
- Недостатки, ограничения и риски

**Ключевые решения:**
- Создание отдельного сервиса депозитов (Java Spring Boot)
- Использование Apache Kafka для асинхронного взаимодействия
- API Gateway для маршрутизации запросов
- Интеграция с АБС через REST API (не напрямую с БД)

### Task4 — ADR: Передача ставок в кол-центр + RoadMap

**Файлы:**
- `ADR.md` — архитектурное решение для передачи ставок в кол-центр
- `C4_context.drawio` — диаграмма контекста C4 (draw.io) — **основной формат для редактирования**
- `C4_context.puml` — диаграмма контекста C4 (PlantUML)
- `C4_context.png` — PNG-версия диаграммы контекста (для быстрого просмотра)
- `C4_components.drawio` — диаграмма компонентов C4 (draw.io) — **основной формат для редактирования**
- `C4_components.puml` — диаграмма компонентов C4 (PlantUML)
- `C4_components.png` — PNG-версия диаграммы компонентов (для быстрого просмотра)

**RoadMap:**
- Детальный план реализации MVP на 6 месяцев
- План целевого решения на 12 месяцев
- Критические зависимости и риски

**Список задач:**
Разбивка задач по 7 системам:
1. Сервис депозитов (новый)

5. Сайт (доработка)

## Технологический стек

### Существующие технологии:
- **Интернет-банк:** ASP.NET MVC 4.5, .NET Framework 4.5, MS SQL
- **АБС:** Delphi, Oracle, PL-SQL
- **Система кол-центра:** Java Spring Boot, React.js, PostgreSQL
- **Сайт:** PHP, React.js

### Новые технологии (MVP):
- **Сервис депозитов:** Java Spring Boot, PostgreSQL
- **Apache Kafka:** брокер сообщений
- **API Gateway:** маршрутизация и балансировка нагрузки
- **.NET Core:** адаптер для интеграции с Kafka
- **Redis:** кэширование справочных данных

## Ключевые архитектурные решения

1. **Микросервисная архитектура** — поэтапный переход от монолита к микросервисам
2. **Event-driven интеграция** — использование Kafka для асинхронного взаимодействия
3. **Изоляция АБС** — избежание прямого подключения к БД Oracle, использование REST API
4. **Горизонтальное масштабирование** — для интернет-банка и новых сервисов
5. **Отказоустойчивость** — резервный ЦОД, балансировка нагрузки

## Цели проекта

### Промежуточное состояние (6 месяцев — MVP):
- Клиент может открыть депозит или накопительный счёт в интернет-банке
- Заявки обрабатываются бэк-офисом вручную (MVP)

### Финальное состояние (12 месяцев):
- Клиент открывает депозит полностью автоматически в интернет-банке
- Бэк-офис не участвует в процессе — всё происходит автоматически
- При обращении в отделение задействованы только сотрудники фронт-офиса
- Сокращение операционных издержек
